    Production Deployment Guide¶

    This guide covers production deployment considerations, security hardening, scalability, and operational best practices for the LGTM Stack.

    Deployment Strategies¶

    Kubernetes Deployment¶

    For production environments, deploy the LGTM Stack using Kubernetes manifests:

    # Example: prometheus-deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: prometheus
  namespace: observability
spec:
  replicas: 2
  selector:
    matchLabels:
      app: prometheus
  template:
    metadata:
      labels:
        app: prometheus
    spec:
      containers:
      - name: prometheus
        image: prom/prometheus:v2.45.0
        ports:
        - containerPort: 9090
        volumeMounts:
        - name: config
          mountPath: /etc/prometheus
        - name: data
          mountPath: /prometheus
      volumes:
      - name: config
        configMap:
          name: prometheus-config
      - name: data
        persistentVolumeClaim:
          claimName: prometheus-data

    Docker Compose (Staging/Development)¶

    Use the provided docker-compose.yml for staging environments with production-like settings:

    version: '3.8'
services:
  otel-collector:
    image: otel/opentelemetry-collector-contrib:0.88.0
    environment:
      - OTEL_TRACES_EXPORTER=otlp
      - OTEL_METRICS_EXPORTER=prometheus
    volumes:
      - ./otelcol-config.yaml:/etc/otelcol/config.yaml
    ports:
      - "4317:4317"  # OTLP gRPC
      - "4318:4318"  # OTLP HTTP

    Security Considerations¶

    Network Security¶

    1. Service Mesh Integration
    2. Deploy with Istio or Linkerd for service-to-service authentication

    3. Enable mTLS for encrypted communication between services

    4. Access Control

    5. Configure authentication for Grafana dashboards
    6. Implement RBAC for Prometheus and Loki access

    7. Use OAuth2/OIDC for single sign-on

    8. Network Policies 

      apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: observability-policy
spec:
  podSelector:
    matchLabels:
      app: grafana
  policyTypes:
  - Ingress
  ingress:
  - from:
    - namespaceSelector:
        matchLabels:
          name: observability

    Data Security¶

    1. Encryption at Rest
    2. Enable encryption for persistent volumes

    3. Configure TLS for data in transit

    4. Secret Management

    5. Use Kubernetes secrets or external secret managers
    6. Rotate credentials regularly

    Scalability and Performance¶

    Horizontal Scaling¶

    1. Prometheus Federation 

      global:
  scrape_interval: 15s
rule_files:
  - "rules.yml"
scrape_configs:
  - job_name: 'federate'
    scrape_interval: 15s
    honor_labels: true
    metrics_path: '/federate'
    params:
      'match[]':
        - '{job=~".+"}'
    static_configs:
      - targets:
        - 'prometheus-1:9090'
        - 'prometheus-2:9090'

    2. Tempo Scalability

    3. Use distributed tracing with multiple Tempo instances

    4. Configure object storage (S3, GCS) for trace storage

    5. Loki Scaling

    6. Implement chunk and index storage separation
    7. Use boltdb-shipper for index storage

    1. Resource Limits

    2. Query Optimization

    3. Use appropriate retention policies
    4. Implement query result caching
    5. Optimize PromQL queries

    Monitoring and Alerting¶

    Alerting Rules¶

    groups:
- name: observability.alerts
  rules:
  - alert: PrometheusDown
    expr: up{job="prometheus"} == 0
    for: 5m
    labels:
      severity: critical
    annotations:
      summary: "Prometheus is down"
      description: "Prometheus has been down for more than 5 minutes."

  - alert: HighMemoryUsage
    expr: (1 - (node_memory_MemAvailable_bytes / node_memory_MemTotal_bytes)) * 100 > 90
    for: 5m
    labels:
      severity: warning
    annotations:
      summary: "High memory usage detected"
      description: "Memory usage is above 90% for more than 5 minutes."

    Health Checks¶

    1. Readiness Probes 

      readinessProbe:
  httpGet:
    path: /ready
    port: 9090
  initialDelaySeconds: 30
  periodSeconds: 10

    2. Liveness Probes 

      livenessProbe:
  httpGet:
    path: /-/healthy
    port: 9090
  initialDelaySeconds: 30
  periodSeconds: 30

    Backup and Recovery¶

    Data Backup¶

    1. Prometheus Data 

      # Backup Prometheus data
kubectl exec -it prometheus-0 -- tar czf /tmp/prometheus-backup.tar.gz -C /prometheus .
kubectl cp prometheus-0:/tmp/prometheus-backup.tar.gz ./prometheus-backup.tar.gz

    2. Loki Data 

      # Backup Loki chunks and indexes
loki-cli backup --backend=s3 --bucket=loki-backups

    Disaster Recovery¶

    1. RTO/RPO Objectives
    2. Recovery Time Objective (RTO): 4 hours

    3. Recovery Point Objective (RPO): 1 hour

    4. Multi-region Deployment

    5. Deploy across multiple availability zones
    6. Use geo-redundant storage

    Maintenance Procedures¶

    Updates and Upgrades¶

    1. Rolling Updates 

      kubectl rollout restart deployment/prometheus
kubectl rollout status deployment/prometheus

    2. Version Pinning

    3. Pin all component versions in production
    4. Test upgrades in staging environment first

    Log Rotation¶

    apiVersion: v1
kind: ConfigMap
metadata:
  name: loki-config
data:
  loki.yaml: |
    limits_config:
      retention_period: 30d
    chunk_store_config:
      max_look_back_period: 30d

    Capacity Planning¶

    1. Resource Monitoring
    2. Monitor CPU, memory, and disk usage trends

    3. Plan for 30% headroom for unexpected growth

    4. Scaling Triggers

    5. Auto-scale based on CPU utilization > 70%
    6. Manual scaling for planned load increases

    Troubleshooting Production Issues¶

    Common Issues¶

    1. OOM Kills
    2. Increase memory limits

    3. Optimize queries and retention policies

    4. Slow Queries

    5. Add query result caching

    6. Use query optimization techniques

    7. Data Loss

    8. Implement proper backup procedures
    9. Use persistent volumes with replication

    Debug Commands¶

    # Check pod status
kubectl get pods -n observability

# View logs
kubectl logs -f deployment/prometheus -n observability

# Debug network issues
kubectl exec -it prometheus-0 -n observability -- curl http://loki:3100/ready
